# Center 实时授权与远端 CPU 故障检查（2026-10-23）

## 已解决的阻塞

现场确认共享NFS的flock互斥不代表文件内容跨机即时可见。新版受控入口现在将活跃账本、许可及启动记录固定在唯一center的本地文件系统，远端不再读取共享JSON作启动许可。共享盘仅保存内容寻址的不可变检查点：预算预留和GRANTED状态均在GO之前持久化。写入失败时不发GO，不改NFS挂载或Mac基础服务。

实现复用标准queue和controller ledger：`authority_backend.py`负责center校验/预留/恢复，`authority_wire.py`负责有界SSH消息与检查点，`authority_worker.py`只执行固定CPU合成动作。实际CLI通过显式`--authority-config`选择该内置后端，`--execute`继续拒绝，不导入动态研究后端。

每次连接使用新session，核验节点host/boot/PID namespace、源码指纹和本地store ID；PREPARE落远端意图、READY返回后center重查owner/epoch/独立许可/全部peer，再持久化GRANTED，fsync后复检许可时限，最后发送绑定本session和任务哈希的GO。远端同一任务只接受一次，10秒内未收到匹配GO即退出。节点/存储变更或本地记录缺失不自动重建、不自动接管。

GO前断联：不启动。GO后断联：已授权的一个有界动作可能完成，不能声称撤销了在途动作。没有完整回执时预算仍预留；只有只读核对远端完整结果、证明处理器已退出后，才能显式恢复新epoch。部分或未知任务没有退款或重发路径。共享检查点可供人工灾难恢复取证，但不得直接作为新许可或自动选取“最新”状态。

## 远端证据

持久运行目录：`runs/center-authority-handshake-20261023/`。

center经真实SSH到Fresh的13个CPU场景全部通过：

- 实际CLI三条合成任务完成；伪造共享ledger快照不影响授权；重复任务、旧session和`--execute`均拒绝。
- GO前终止本次SSH运输进程、远端等待超时、旧epoch、撤销许可、检查点写入失败、检查点期间过期：均0次远端启动，预留保留。
- 丢ACK：保留预留，显式核对完成凭证后升epoch，再完成剩余合成任务，已执行任务没有重复。
- 部分块：有启动记录但无完整凭证，拒绝恢复/退款/重发。
- 控制器进程在GO前/后突然退出：分别0/1次启动，未知保持阻塞，完整凭证才能恢复。
- 重复控制器和不可用远端解释器入口：拒绝派发。

第一次现场测试脚本将锁竞争异常误写为RuntimeError，实际返回BlockingIOError并正确拒绝；修正断言后只补完两个未完成场景，已完成的测试未重放。原始日志和修正脚本都保留。默认portable测试仅使用本地CPU子进程，不自动连接远端。

## 正式派发边界

本轮模型调用、训练、评测回合、GPU仿真均为0；原672条任务及48/240/384阶段预算不变，原custody仍PAUSED、dispatch_enabled=false、无任务预留。CPU合成账本与研究预算完全分离。

当前通道不是模型执行器：真实LIBERO适配器的worker启动/结果凭证还需接入相同授权边界，并完成科学输入/模型轨迹及容量准入；新运行绑定和用户许可均未签发。Fresh先前单初态首帧检查通过不能替代这些步骤。

旧冻结源码和GNU/Video的旧副本仍有绕过路径；当前源码已硬关闭旧标准队列、fleet和直接worker边界，但不是操作系统级隔离，也不防御持有同等SSH/root权限者手工运行任意代码。正式派发前须逐机审计实际入口、部署核对受控版本、只发布新入口和显式绑定；冻结副本保留取证，禁止重放，不通过真实worker试运行验证绕过风险。

中心重部署后停止所有派发，先核对共享不可变检查点及远端store/任务凭证，再人工恢复本地控制数据、核对所有预留并建立新身份/epoch/期限。未明确消耗不得清零，不能因重启沿用旧PID、旧许可或旧截止时间。详细恢复步骤、SHA256、测试与Git状态见持久运行回执。
