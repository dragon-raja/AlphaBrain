# 六组P3/原生完整前缀小试

用户明确批准六组小试和66,000次新增调用硬上限。配置在持久项目的 `runs/prefix-ppo-comparison-20261102/protocol-r2.json`；不复用已关闭的RLDX网格预算，不自动扩大训练。每模型P3/full各256回合、8个完整32回合更新、种子0；端点Stay/P3-PPO/full-PPO各64条配对操作，合计576条。采用原G奖励，操作模型冻结，不同时修改奖励、STOP、网络或查询成本。

完整前缀分别为π0.5 P10、GR00T/RLDX P4。去噪轴与动作轴分别绑定：π0.5保留历史评分10动作/执行5动作，GR00T评分执行均10，RLDX评分执行前8动作/真实7维。完整前缀不是独立噪声平均，也不保证比P3更好；这轮仅用于开发机制判断，不能宣称收敛或最终留出泛化。

可复用接口：`data/score_prefix.py`声明轴；`metrics/score_prefix.py`计算评分；`score_prefix_runtime.py`仅装饰score，不改变采样器、动作和特征；`prefix_pilot.py`接标准controller ledger与版本屏障，actor来源额外绑定模型/特征/初始化/评分合同。旧冻结入口和结果不修改。

RLDX的64个联合认知query不是8×8像素网格，使用单个joint流、四组有序query均值；所有token保留参与，不伪造腕图。`rldx_search_runtime.py`保留原生四帧历史、逐动作更新、16预测/8执行和配对原生随机种子。原生布局必须逐层传到采集器、Gym和搜索会话，不能根据维数重建空间布局。

本次实际暴露并保留的工程失败：首版快照漏掉仿真器延迟导入的scripts依赖，零模型调用；借用节点的旧观察器将保活子进程更换锁存为HOLD；RLDX序列布局未传入会话导致两组各6次已知调用后拒绝，零PPO更新。分别落盘失败日志、源码、在途审计和epoch隔离。新版本或恢复绑定须通过独立依赖闭包、完整采集/PPO CPU回归和真实入口验收；不明消耗不退款、不自动重发。

cy只读监测继续校验原supervisor出生、可信release/executable和每次真实子进程/UUID，修复观察器的缺失/proc采样竞态不等于控制保活。新观察代次必须显式审计创建，旧HOLD保留。研究任务阶段保留0/7号位置，六卡采集，不修改保活策略。
