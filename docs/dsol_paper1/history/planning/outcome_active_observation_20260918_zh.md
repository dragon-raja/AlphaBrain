# 面向 VLA 的结果驱动主动观察：算法设计与实现契约

日期：2026-09-18。状态：`CPU_CONTRACT_PROTOTYPE_NOT_LEARNED_NOT_EXECUTION_RELEASE`。

本设计回应用户要求：下一阶段不再限于初态模板/选择器，而研究任务执行中的主动观察、本体随动及基于执行结果的学习。现有静态评测、条件场和 RoboCasa 工作继续；不修改冻结协议、运行源码、调度或当前 PDF。本文件是下一阶段方法设计入口，不是新实验已获验证的报告。

承接 [主动桥接计划](paper_master_plan_v2_active_bridge_20260907_zh.md) 的问题边界，具体化其尚未实现的学习循环；不继承其中已过时的预算和 O/P/Q 执行安排。静态选择器保留为基线，不作为本方法终点。

## 1. 中心问题、拟机制与非贡献

中心问题：给定操作策略 π，机器人能否通过任务结果学会在执行过程中何时观察、如何移动相机、何时继续操作，并适应相机随底盘/躯干运动的条件？

拟机制：用合法历史与操作模型反馈提出观察动作，预测短时观测特征并评价对当前操作模型的任务收益；用真实转移校正预测，用完整任务结果校正价值，再把搜索判断蒸馏为有记忆、受运动约束的相机策略；在该策略实际访问的状态上继续收集反馈和更新。无预测器的直接价值学习作为对照，不是默认假定预测器一定必要。

待验证的关键点不是“分数更低”，而是：观察收益监督是否比成功率预测/原始分数更有效；本体运动条件是否改善随动情况下的判断；反馈更新是否在等交互成本下产生新回合收益。

相机 RL、条件价值、DAgger 式数据聚合、坐标变换、策略蒸馏本身均为已有思想。框架模块数、增加工作量或使用“自进化”名称不构成新颖性。以下是具体研究设计，不承诺优于近邻或获得顶会接收。

### 1.1 方向与术语：结果驱动的模型辅助主动观察学习

工作名称：**结果驱动的模型辅助主动观察学习**（Outcome-driven Model-assisted Active Observation Learning）。这是描述性工作名称，不是已验证方法品牌。研究领域是主动感知/主动视觉与机器人学习；部署形态是冻结操作 VLA 的外接观察策略；拟采用的训练机制是结果监督的价值学习、短时预测、搜索蒸馏与策略访问分布上的数据聚合。

统一优化对象是观察策略 μ，而不是 Accel 本身：在固定操作策略 π、合法可达/安全动作与明确交互预算下，优化 J(μ;π)=E[Y−λ_t·T−λ_q·N_query]。Y 是完整任务结果，T 是计入相机移动与操作的物理时间。报告时成功率、时间和查询次数分开列出；λ 与预算须开发集选定后冻结。任务是部分可观测、option 持续时间可变的序贯决策问题，历史 h 只近似状态，并不自动是充分的 belief state。所有模块应服务于这个共同目标，而不是各自以预测精度/Accel降低为最终成功判据。

- **没有 PPO 不等于没有 RL**：若从交互回报估计 Q，并用模型辅助搜索改进策略、再收集经验，就可以从广义上归入模型辅助的近似策略迭代/模型式强化学习。具体是否采用 Bellman 更新、策略梯度或仅蒙特卡洛价值回归，必须按实际训练目标说明，不能以名称替代算法。
- **不称标准 DAgger**：教师不是给定的可靠专家，而是有限预算、有噪声的分支搜索。数据聚合借鉴 DAgger，但不继承其专家条件或理论保证。
- **不把重复训练称为持续学习贡献**：持续学习还需任务/场景序列、受控适应预算、遗忘与迁移评估。当前优先是固定训练/测试划分内的迭代策略改进。
- **自进化是待验证属性**：需多轮真实反馈之后，在独立回合上改进，并优于同总数据/交互预算的一次性训练。单回合记忆更新、推理搜索或只有更多训练步不满足这个证据要求。
- **当前代码没有 RL 训练器，也没有神经网络训练完成**：CPU 契约原型不能被称为已实现 MBRL/DAgger/持续学习系统。

Motus2 官方工作使用共享参数的 policy/simulator/evaluator，并以 DiffusionNFT 将价值信号用于策略后训练，明确归为模型式强化学习；另有不更新权重的 Best-of-N 推理规划。我们可以借鉴预测—评价—改进结构，但当前只针对观察动作、冻结操作 VLA，不复制其通用视频动作世界模型，也不因接口相似即获得新颖性。来源：[Motus2 官方项目](https://motus-robotics.github.io/motus2/)、[论文](https://arxiv.org/abs/2608.30237)。

第一版优先搜索蒸馏与结果价值学习；recurrent PPO 为同预算对照。只有当搜索教师限制明显、且原型链路有效时，再比较教师预热+RL。端到端 VLA 更新、持续学习、长时想象 rollout 均非首版必需项。不是排斥这些方法，而是先分清收益来自哪里。

## 2. 双循环与模块

单回合：合法历史 → 观察策略 → 继续操作/相机动作 → 实际获取图像 → 冻结 VLA → 环境反馈 → 更新历史。

跨回合：训练经验与配对分支 → 收益模型更新 → 相机策略更新 → 新训练回合 → 独立评估回合。

| 模块 | 输入 | 输出 | 第一阶段训练状态 |
| --- | --- | --- | --- |
| 操作策略 π | 原图像槽、语言、本体输入 | 原操作 action chunk | 冻结，保留原接口 |
| 历史编码器 H | 已获取图像、动作、相机局部运动、本体状态、时间、模型反馈 | 观察决策记忆 h | 可训练的小型时序模块 |
| 短时观测预测器 W | h、局部相机 option、已知执行模式/时长 | 到达后的观测特征分布 | 真实转移监督；首版不生成整段 RGB |
| 观察收益模型 A | h、可执行相机选项 u、当前 π 身份/训练处理 | 相对继续操作的预期收益与估计不确定性 | 配对分支监督 |
| 相机策略 μ | h、运动约束、剩余时间/查询预算 | continue 或相机选项 | 教师预热后在线更新 |
| 本体/相机适配器 | 当前支撑体位姿、关节、动作请求 | 可行局部相机轨迹、实际位姿与代价 | 确定性工程组件 |
| 经验与评估账本 | 真实执行、分支、策略版本、噪声身份、最终结果 | 可追溯训练样本和独立评估记录 | 不学习、不访问未授权测试标签 |

第一版不把历史图像硬塞进现有 VLA，也不增加原有图像槽。相机策略有记忆不等于操作 VLA 有视觉记忆。需要“看后移开仍能操作”的能力时，另设操作记忆适配实验，不混入相机策略收益。

## 3. 统一时序：以动作段边界为观察决策点

使用受约束、带持续时间的部分可观测决策过程。第一版采用分层 options，不改 Flow 去噪过程，不逐仿真帧调用大型 VLA。

1. 正常完成一个操作执行段，在下次 VLA 重规划前，读取允许的观测和历史。
2. μ 选择 continue 或一个相机 option。continue 使用当前观察产生下个操作段。
3. 相机 option 包含局部目标、路径、持续时间、观测时点及机械臂/底盘执行模式。
4. 实际推进环境与相机，读取新观测后再调用 VLA。相机移动本身不额外消耗操作 Flow RNG。
5. 成功、终止、预算耗尽和执行异常均明确记录，不将失败移动静默改记为 continue。

首个可验收模式为 move-and-hold：保持经验证的操作控制目标，物理时间照常推进。它不等于冻结 qpos；零动作不等于夹爪/控制器保持。随后加入 move-with-execution：头部移动期间继续执行既定操作段，观测与重规划规则保持明确。后者才用于验证运动中的随动，不用前者冒充。

首次实现不在 action chunk 中途任意取消队列。若研究中途重规划，另定义废弃动作、噪声索引、时间成本与安全处理。

Flow 噪声以 (episode, 操作重规划索引, 噪声域) 显式寻址；评分噪声与执行噪声分离。不同方法调用次数可以不同，共同索引的配对只保证外生随机输入对应，不保证轨迹/语义时刻相同。最终比较仍需跨独立噪声与初态。

## 4. 相机与本体耦合

对主动头部使用 T_WC = T_WB · T_BH(q_head) · T_HC。世界位姿由底盘/支撑体、头部关节和安装关系共同决定。动作在局部关节或相机坐标定义，不要求知道训练规范位姿。

第一阶段分开报告两个条件：

- 独立运动学外部相机：不随操作本体移动，用于分离观察策略机制；不是实体头部动力学验证。
- 支撑体随动的主动相机：保持父体安装关系，主动相机运动与底盘/躯干随动共同决定图像；策略接收可获得的本体运动与将执行的动作段。不能输入未来真实底盘轨迹。

两者不共享虚假的自由 SE(3) 可达域。头部 pitch/yaw 无法产生平移视差；若相机轨道允许平移，其动作集和成本单列。腕部通过机械臂动作改视角会改变接触和可操作性，属于后续独立条件。

运动补偿与坐标变换是必要工程，不自动是算法贡献。通过“无本体信息/有本体信息”“无时序记忆/有记忆”“静止支撑体/随动支撑体”的受控对比，判断学习部分是否有实际价值。

## 5. 训练信号：观察收益，而非仅预测难度

对固定操作策略 π 和冻结的后续观察策略 μ_k，定义：

Q_k(h,u) = E[Y - λ_t·剩余耗时 - λ_q·额外查询数 | h, 首个选项 u, 后续 π 与 μ_k]。

A_k(h,u) = Q_k(h,u) - Q_k(h,continue)。

安全/碰撞/可达性先作为硬约束，不靠减小罚项接受不安全动作。成功、时间、查询和路径长度仍分别报告；成本权重在开发数据上选择并于评估前固定，另给预算曲线，不按测试涨分调权重。

### 5.1 配对干预教师

从训练回合按预定时间/阶段分层与随机抽样取决策点，恢复完整状态，并保留当时合法的历史与 μ 记忆；每点比较 continue、少量合法局部动作和匹配时长 hold。

- continue 比较实际净收益；matched-hold 辅助区分相机观察和单纯等待效应。二者不能互换。
- 各分支运行到成功/统一时限，使用共同执行噪声索引并有多次重复。全部计入训练成本。
- 后续使用同一个 μ_k，避免把相机第一步与不同续行算法混成标签。
- 仿真特权状态只用于恢复、安全判断和训练标签，不进入部署 actor 输入；若 critic 使用特权输入，必须显式标注且单独蒸馏到合法输入。
- 标签是该续行策略下的有限样本估计，不是严格动态 Oracle；更新 μ 后标签可能过时。
- 实际只执行一个分支时，不能给未执行候选伪造结果。

第一版训练损失使用配对收益回归与可靠差异上的排序损失；保存标签方差，接近零或样本不足时不强制赢家分类。不把所有失败样本视为无价值，也不将成功分支一律当成应模仿的动作。

### 5.2 教师蒸馏与闭环更新

首轮 μ 用收益教师产生的软排序/动作目标预热。然后运行 μ_k，针对其访问的状态补充分支反馈，更新 A 与 μ，形成 k→k+1 循环。保留历史样本，并按操作模型版本、续行策略版本和本体条件分组；不能无条件混合不同 π 的旧价值标签。

这个过程采用近似搜索教师的数据聚合，不宣称直接获得 DAgger 的理论保证。Accel 只作为可观测特征/候选先验，必须保留不依赖 Accel 的探索覆盖，避免候选被先验永久排除。

对照路线是相同输入/动作/预算的小型 recurrent PPO，只训练相机 actor/critic。物理持续时间进入回报/折扣，不能把长短 option 当成等时动作。相机策略可用普通概率分布，不需要计算冻结 Flow VLA 的动作似然。

若采用配对教师预热后再 RL，必须比较教师单独、RL 单独、组合，且总交互/分支预算匹配。不能将组合多花的数据解释成算法优越性。

## 6. 学习目标与适应协议

先学习“让当前任务成功的观察”，不把预测误差最大化作为默认奖励。为了学习本身而主动选择经验，是另一个跨回合探索目标，不能与单回合任务价值混称。

训练、开发、确认按独立初态来源/场景分开；声称未见任务泛化时按任务留出。已有看过结果的初态仅作开发或历史比较，不再次称盲测。

跨次适应独立设定：每个评估场景允许 N 次明确记账的适应交互，冻结更新后在新种子/新回合测试；零次适应与多次适应单列。报告 SR(N)、观察/计算成本、旧场景保持情况。评估回合不用于调参或更新。

第一阶段 π 全程冻结。若以后联合更新 VLA，必须补 (相机固定/更新)×(VLA固定/更新) 因子对照，避免把操作训练收益归给观察。

按 2026-09-18 最新讨论，短时观测预测器进入拟验证主路线；无预测器的直接价值方法保留为必要对照。预测器不是 CPU 接口验收和运行适配的前置，也不预设其必然优于直接价值学习。静态相机视频模型不能默认外推主动相机动作。

### 6.1 最小学习目标与融合顺序（尚未实现训练）

设 h 为合法历史，u 为相机 option，z' 为真实到达观测的编码。首版采用一个 option 的预测与后续价值，不在预测特征中模拟完整操作任务：

1. W(h,u) 预测 z'，用实际相机运动转移拟合；损失由特征表示选择决定。初始可用特征回归，但必须和常量/当前特征复制基线比较。
2. G(h,u,z',π,μ_k) 学习该操作模型与固定续行观察策略下的真实任务回报。部署时用 W 的预测输入，需要验证真实特征训练到预测特征推理的分布差异；开发数据交叉拟合/预测扰动是候选处理，不冒用训练样本拟合值证明泛化。
3. 比较预测收益与 continue，选择合法 option。真实分支结果可校正搜索教师；想象结果不冒充真实成功标签。
4. μ 用搜索软目标蒸馏，运行 μ_k 收集新转移和结果，产生下一轮训练数据。低置信、收益接近的教师标签不强行设唯一赢家。

先完成可替换的独立接口，再比较共享历史编码器+多头。参数共享不等于所有损失同时反传；首先冻结视觉编码器和操作 VLA，分别核验预测与价值，再研究共享历史表示以及停止梯度/分阶段更新。不能让价值头通过改变预测表示制造高分而失去实际观测含义。参数融合后仍保留逻辑接口和消融开关。

规范/多视角操作模型可能有不同视觉编码器：必须固定共享编码器身份，或分开预测模型，价值必须明确条件于操作模型身份。不能把两种模型的特征坐标与回报无条件混为一谈。当前 CPU 协议用版本 ID 做身份约束，真实权重哈希核验由未来适配器负责。

部署给 VLA 的始终是真实 RGB；预测特征仅用于观察决策。首版 move-and-hold 不输入未来真实底盘轨迹；之后 move-with-execution 需要新增已知操作指令和持续时间契约。腕部耦合不是外部相机 option 的无成本替换。

## 7. 最小实现与验收路线

本节是工作顺序，不是已启动任务或执行时间承诺。数值规模、任务清单与资源安排写入未来独立 release 后才跑正式实验。

| 步骤 | 具体交付 | 验收标准 |
| --- | --- | --- |
| I0 | 数据契约、事件时钟、局部相机 option、动作队列与预算测试 | 纯 CPU 测试，无 GPU/仿真副作用 |
| I1 | 一个环境的全 rollout 适配器 | no-op 等价；有实际相机移动与新观测；耗时入账；失败不丢失 |
| I2 | 完整状态+控制器+历史+RNG 的分支恢复 | 同分支重复一致；跨分支无污染；controller、gripper、图像缓存都核查 |
| I3 | 少量预定任务上的 continue/hold/初态搜索/动态规则参考 | 覆盖容易、初始扰动、过程信息变化，不按涨分筛任务 |
| I4 | 配对收益教师、时序 actor、一个结果更新循环 | 训练标签可追溯，actor 无候选图/结果泄漏；新回合验证 |
| I5 | 多轮更新、等预算 RL 与教师消融、支撑体随动 | 学习曲线、时序/本体输入贡献、稳定性与保持能力 |

I3 是运行与任务可解性核查，不是要求静态 Oracle 显著后才进入动态学习。动态收益若不足，先区分任务不需要新观察、动作域受限、VLA 不能使用新图、执行成本和策略学习失败；不自动增加所有数据和候选空间。

首轮采用少量局部动作 + continue，允许完整 rollout 在多个动作段边界反复决策；不把“全 rollout”缩回初态一次搜索。受控触发时点用于工程/教师诊断，最终 actor 必须能决定是否观察。

## 8. 与现有代码的关系

已检查的工程资产：

- `AlphaBrain/research/dsol/acquisition/motion.py`：轨迹/预算，可复用后扩展局部安装条件。
- `acquisition/executor.py`：端点获取；当前严格位姿误差要求适合运动学执行，不直接适用有跟踪误差的真实头部。`PersistentOSCGoalHold` 仅审计过单臂 Panda，不得直接用作 RoboCasa 移动本体 hold。
- `acquisition/discrete_search.py`：静态缓存查询基线，不能作为动态环境 transition。
- `benchmarks/Robocasa365/camera_rig.py`：保存父体局部安装，适合核查随动；现有 ReferenceRig 是固定状态校准工具，不是全 rollout 主动相机策略。
- `metrics/noise_rules.py` 及已冻结噪声协议：复用概念但重新验证动态调用时序，不冒用历史验收。

建议实现归属：相机与预算契约进入 `acquisition`；历史编码/actor/价值模型进入 `selectors`；训练经验校验进入 `data`；结果学习分析进入 `analysis`；具体仿真适配在对应 runtime/benchmark 层；CLI 保持薄入口。不要复制一套独立研究工程，不让 core import benchmarks/scripts。

截至本次更新，纯 CPU 协议、可替换规划接口及事件状态转换已经实现，见第 11 节。神经网络 actor/predictor/value、教师训练、真实环境动态 rollout 和参数更新循环均未实现，未启动新框架训练。现有其他任务的未提交代码保持原样。

## 9. 基线、消融与创新风险

必须包含：保持原位、开发集默认方案、初态一次搜索、匹配预算随机/周期相机、动态 Accel、视觉/可见性反馈、小型普通 RL、配对教师方法。模板不是“垃圾”，它用于检验复杂方法是否确实必要。

核心消融：相对收益监督 vs 成功率监督；反馈有/无；时序有/无；本体运动有/无；持续更新 vs 相同数据的一次性离线训练；匹配教师/交互成本。不同本体动作域单列，不靠更大的自由相机空间赢过受限头部。

可声称的贡献必须由结果决定：

1. 若只比受扰动保持更好，不能声称解决了动态观察或结果学习。
2. 若普通 RL 同等预算同样有效，专门教师机制的优势未建立。
3. 若本体输入消融无差异，不能把通用坐标处理包装成耦合学习贡献。
4. 若动态 VLA 无法利用新视角，需单独研究执行适配；不能预先排除所有主动感知价值。
5. 若新机制在匹配条件下有效，再提炼失败来源、有效机制和可迁移规律，而不是先固定贡献数量。

## 10. 近邻与设计来源

- [OTA](https://hymwgk.github.io/ota/)：观察/操作交替及 RL，不主张首次。
- [SaPaVe](https://arxiv.org/abs/2603.12193)：相机与操作解耦训练；动态头部近邻。
- [See2Act](https://arxiv.org/abs/2606.23625)：去噪与视角细化结合；本方案首版不介入 Flow 内部，而研究结果监督的外层观察决策。
- [LIME](https://arxiv.org/abs/2607.02417)：意图条件相对相机位姿，可作为提议器思路；不等于已评估当前 VLA 的结果收益。
- [Sea²](https://arxiv.org/abs/2602.23806)：冻结下游模块、反馈训练相机，不主张这类通用架构首次。
- [RISE](https://arxiv.org/abs/2602.11075)、[World-Gymnast](https://arxiv.org/abs/2602.02454)、[Motus2](https://arxiv.org/abs/2608.30237)：反馈/价值驱动的策略改进与世界模型路线；本方案先训练观察策略，不复制大模型训练规模。
- [DAgger](https://proceedings.mlr.press/v15/ross11a.html)：策略访问分布上的数据聚合；近似教师条件下不直接继承保证。

文献比较仅确定已知重合与拟区别，不证明不存在更近邻；正式方法冻结前须对最终机制再次检索。

## 11. 当前 CPU 原型及 P0 并行边界

代码归属（仓库根目录相对路径）：

| 实现 | 内容 | 不代表什么 |
| --- | --- | --- |
| `AlphaBrain/research/dsol/data/active_observation.py` | 不可变真实观测/动作历史、模型版本、option、预测、获取回执、结果样本及训练准入 | 不能证明调用方没有伪造输入来源；不是持久化数据发布器 |
| `AlphaBrain/research/dsol/selectors/observation_planning.py` | proposer/predictor/evaluator/feasibility 接口，预算内比较 continue 与观察 option，显式无预测消融 | 没有学习权重、网络或优化器；假模型分数不是研究结果 |
| `AlphaBrain/research/dsol/acquisition/observation_loop.py` | 物理时间、获取失败记账、操作重规划计数、执行噪声地址、终止控制 | 不调用仿真，不执行相机，不验证真实控制器安全 |
| `tests/dsol_paper1/{data,selectors,acquisition}/test_*observation*.py` | 合成输入端到端计划—获取—操作测试及边界拒绝测试 | 不是 no-op 实际轨迹一致性或闭环成功率验收 |

已实现的最小行为：只有真实获取类型进入历史；动作历史必须早于当前观察；开发/测试结果不能进训练；操作/编码器/续行策略身份不匹配的标签拒绝；不能隐式截断候选以满足预算；预测次数与实际获取次数分别计数；相机评分/获取不递增操作噪声索引；失败移动保留实际时间、真实端点和失败状态；continue 不产生相机查询；时间到期不能再执行动作。

初版 option 的 target 是由 embodiment_contract 解释的不可变数值元组，不假设自由 SE(3)；长度、单位、局部坐标定义、路径安全与可达性需真实适配器显式验收。AcquisitionReceipt 的 arrived/failed 也不是安全认证。operation.commands 记录实际执行的指令样本；其控制频率、tick 单位由适配器契约明确，CPU 层不臆定“一条指令=一仿真步”。

当前状态转换只支持动作段结束后的 move-and-hold/matched-hold/continue，不支持并发动作或中途取消。噪声地址是 episode/repeat/replan/domain，不包含候选位姿；实际噪声张量仍需采用已冻结的独立评分/执行噪声实现与来源凭据。

P0 与新框架安排：

1. P0 两臂训练、400 初态参考验收和静态主线评测优先，冻结运行源码不改。
2. 当前工作仅在 CPU 上实现独立新模块、测试和设计；无新增 GPU 作业、后台监视器或自动执行入口。
3. 静态渲染缓存不是移动转移数据，更不是完整任务结果。正式评测需最终权重、参考 release、当前参考适配、视角安装与整任务运行一致性、两机适配验收、明确噪声预算。
4. 现有 RoboCasa policy probe 是工程诊断，仍使用历史图像参考且不支持正式 97 位姿双机矩阵；不能把它直接放大运行冒充正式评测。正式 noise_budget 仍待冻结；不继承旧 LIBERO 的 32 次或擅自减初态。
5. 新框架后续先接单环境真实运行，验收 continue 等价和有时长的相机移动，再采有限动态转移/续行反馈。无需等待 P0 所有结果，但需独立资源安排和实验预算。

尚未完成：数据序列化读取器/发布校验、真实编码器、学习模型与训练器、实际动态适配器、完整状态分支恢复、跨机正式评测驱动。这些不因 CPU 测试通过而自动视作已完成。
