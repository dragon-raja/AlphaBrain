# Center双worker接入与通信优化（2026-10-23）

原框架已有多worker队列、owned进程和显存峰值预留。本次补齐新center实时授权适配层对同卡兄弟worker的识别，不更换科学执行循环。旧框架存在的能力此前没有完整接入新入口。

候选由`resources.worker_slots`生成每机16个槽，第一轮先填八张物理卡，再填第二个worker。`worker_gpu`在物理卡启动锁内核验同绑定、同owner/epoch、同阶段、本地store、进程出生时间/进程组/解释器身份；复用原`gpu_guard`，不降低13,500 MiB加载峰值和2,048 MiB余量，不放行未知或未结算占用。资源配置转换只改资源槽，不改任务key、科学request、预算或旧绑定。

通信优化收集当前可读CHECK，先向全部节点发送本轮心跳，再锁定center本地账本重读许可与owner/epoch，逐worker回复精确下一序号。心跳不是跨轮缓存，不发未来调用额度；许可在探测期间撤销则本轮零放行。断联、过期、缺失回执和部分失败继续保留预留，只能显式恢复。队列仍在每次新启动后服务已有worker。

CPU证据：portable 454 passed / 15 skipped。三机各16个低优先级CPU模拟worker，分别进行64次授权检查，共3072次CHECK；串行路径91.876秒、批量路径64.065秒，约减少30.3%墙钟时间。账本读取从10105次降到905次；批量继续许可阶段112轮、336条心跳、3072个独立CONTINUE，单轮最多48个。两种模式均完成48个合成任务，零真实episode、零模型调用。此为一次CPU运输对比，包含SSH启动成本且受当时负载影响，不能声称真实GPU推理加速1.43倍。

当前672条评测已进入最后正式阶段，保持r4科学worker/r5控制器及原24槽绑定。候选位于独立release和CPU队列，未热替换、未转派Fresh任务、未新增或重放科学任务。候选代码、源码快照、测试日志和模拟控制状态保存于持久项目`runs/center-dual-worker-20261023/`。

后续使用：在当前冻结阶段自然结束后，为下一批已授权科学任务建立独立候选绑定与当前主机身份。先对空闲物理卡做双worker实际吞吐/显存峰值/协议一致性对照；复用计划内任务与预算，不重复已完成任务。只有三模型分别测得收益且协议一致才扩至每机16槽。两worker共享显存不保证吞吐翻倍，训练DDP/PPO也不直接套用评测容量。若本轮672条先完成，不为验证加速另启动实验。旧冻结副本仍可由同权限用户手工执行，未宣称系统级隔离。
