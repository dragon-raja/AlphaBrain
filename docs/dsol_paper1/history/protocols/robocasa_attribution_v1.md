# RoboCasa P0 补充归因验证

本实验是完成 P0 后、看到结果再设计的探索性归因验证，不替换 P0，也不冒充事前注册的确认性研究。当前报告保留原始数据来源；补充结果验收后再合并进入唯一报告。

## 权重时间轴

在原来的 10 个任务、400 个初态（seen / heldout 各 200）上，比较官方 Human300 75k 起点、两组各自 4000 步权重、已有的 8250 步结果。不重训。规范与多视角训练都从同一个官方权重出发。

新增评测采用 13 个仅由几何决定的视角：规范视角，训练网格内层/外层各 4 个对称四面体顶点，以及从 extra32 中按归一化参数距离 maximin 选出的 4 点。每格沿用 P0 的 4 套执行噪声及 8 套初态评分噪声。三个新增权重共 62,400 次完整闭环；末期权重的同格结果直接复用 P0。13 点仅是几何诊断面板，不能用其均值代替 97 点全空间均值。

新噪声确认已获用户明确批准（2026-09-23）。每模型每初态固定规范、最低 8 噪声平均 Accel、原 RGB+Accel、原 4 噪声均值 Oracle 赢家，补执行 repeat=4..11。若多个方法选到同一视角，只评一次并共用结果；上限 25,600 次，冻结后去重为 22,840 次。不根据新结果换赢家，也不根据成败选择补采。它估计原赢家/方法在新噪声上的表现，不宣称获得真实总体 Oracle。不得把这一步下降自动解释为视角空间没有价值。

## 不变项及工程验收

- 原任务、初态、物理状态、视角安装方式、腕部、原生底盘动作、任务时限、成功判据、10 步 Flow、25 步 replan、native 4x MSAA 全部保持不变。
- 使用 P0 的闭环实现和地址化噪声函数；旧数据、代码快照、归档报告不改写。
- 候选安装选择后全程固定在机器人上的相对安装偏置；不是过程中选择视角序列。
- 新权重面板重新渲染并通过原像素门槛。确认实验复用原模型对应候选的实际首帧输入，后续闭环仍用原生渲染。渲染微差仍然存在，不宣称逐位确定性。
- 两机已存在的保活或其他任务不停止。诊断使用独立输出、源码冻结及权重哈希。每阶段单独进程，避免旧权重占用显存。
- 先用 seen 初态做加载、trace/infer 一致性、完整轨迹及吞吐验收。任何门槛失败停止对应 worker，不能自动放宽。

## 离线分析与归因边界

1. 训练效果：按任务、seen/heldout、内外几何分层，比较 0/4000/8250；训练过的视角与额外视角几何分布不同，不能直接把均值差归因于记忆。
2. Accel：固定原主指标 prefix3。看每初态秩相关、低分分位收益、8 评分噪声的排名稳定性及各任务差异。其它 prefix 仅作敏感性诊断，不根据测试成功率重新指定主指标。
3. Oracle：先对噪声平均再选视角；补充所有 2+2 划分和独立噪声确认。2+2 的筛选样本更少，并不等价于真实 Oracle 估计。
4. 相机依赖：本轮不直接用黑图遮腕就断言腕部捷径；这种输入本身会造成分布外扰动。需要预注册的传感器消融才能作较强因果判断。
5. 不把 RoboCasa 与 LIBERO 的差别单因归为 benchmark、机器人或训练覆盖；两者同时改变多项因素。
6. 存档 trace 的动作子空间敏感性：原指标使用 50×32 内部坐标，而 RoboCasa 输出前 12 维、每次执行前 25 步。离线重算 full32×50、active12×50、active12×25、unused20×50，检查填充维度和未执行块对排序的影响。它是探索性诊断，不直接替换主指标，也不把测试集挑出的变体宣称为已验证新方法。
