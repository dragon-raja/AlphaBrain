# 仓库架构与维护边界

本仓库同时承载 AlphaBrain 框架和 Paper 1 研究，不把二者混成一个实验脚本包。

| 层 | 位置 | 职责与依赖方向 |
| --- | --- | --- |
| 共享基础 | `AlphaBrain/common` | 图像与记录编解码；不依赖模型、训练、部署或研究 |
| 框架 | `AlphaBrain/model`、`dataloader`、`training` | 模型、数据、训练能力；只依赖包内能力和外部库，不反向 import scripts/deployment |
| 研究实现 | `AlphaBrain/research/dsol` | 指标、选择器、统计、可视化、获取工程原语；不 import 脚本或报告 |
| 执行适配 | `scripts`、`benchmarks`、`deployment` | 参数、运行编排、环境和服务适配；调用核心包 |
| 报告 | `reports/paper1` | 消费结果与图表，负责布局和输出 |
| 人类文档 | `docs` | 设计、协议、结论、执行记录、报告产物；不放可执行 Python |
| 验证与治理 | `tests`、`tools` | 测试、静态边界、发布前检查；默认不申请 GPU |
| 历史研究 | `archive` | 原源码与迁移证据；不作为新实现的运行依赖 |

## 入口与数据分离

仓库根目录保留项目元数据、说明与构建配置。`scripts` 根目录的配置解析、模型下载、环境 smoke 和训练／评测入口是框架公共命令，并非散落的研究算法。新实验命令进入对应职责目录。

模型权重、原始 rollout、缓存数组和凭据不放进源代码包。实验目录的冻结 `repo/`、release、旧来源哈希不因维护工作重写。公开／私有资产分离规则以 `.gitignore` 和发布前人工审查共同落实。

## 当前明确保留的兼容边界

- Paper 1 脚本根目录仍保留 37 个入口和运行依赖，其中包括活动控制器核验的路径／哈希目标。这不是新代码的组织范例。
- CABI 仅保留当前基准和兼容链所需的 12 个文件；其他历史研究整体归档，不按文件名猜测其科学价值。
- 图像工具和配对记录工具各只有一份核心实现，旧导入路径保留薄别名。
- 历史脚本按职责整理并不等于它们全部成为通用 API。需要复用时先抽取接口及测试，禁止复制成另一个版本。

运行链整体切换需要新源码版本和完整轨迹一致性验收。此次静态／CPU 验证不冒充所有模型、所有机器人环境的运行认证。

## 变更与验收

1. 确认职责、消费者、运行进程及冻结身份引用。
2. 保存原字节和路径映射；先建立测试，再改导入或拆模块。
3. 重构与科学协议变化分开，不能借维护改变任务、初态、噪声、训练配置。
4. 执行仓库检查、相应测试配置、打包与导入验证。
5. 审查 staged 文件中的私有资产、凭据、体积与无关改动，再提交／推送。

命令见 [测试说明](../../tests/README.md) 与 [开发规范](../../CONTRIBUTING.md)。历史迁移收据原样保留，后续迁移通过带前后哈希的新记录建立连续来源链。
