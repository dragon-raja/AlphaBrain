# Center三机真实模型入口准备（2026-10-23）

真实LIBERO适配器已接入标准队列、controller ledger和center实时授权链。模型执行仍需用户对具体阶段授权；准备目录不包含有效生产permit。

`execution/model_authority.py`复用预算预留/GRANTED/GO事务，保留SSH工作通道及每节点心跳通道。每次模型调用前由当前center核验owner/epoch、期限和全部节点连通性；连接失效不自动重连续跑。每个任务拥有独立本地锁和进程组身份；恢复既要完整结果凭证，也要证明所属进程组退出，未知消耗不退款、不重发。

`benchmarks/LIBERO/continuous_authority.py`固定执行原paired/nominal循环，CPU合同模式不能进入模型函数。正式模式在GO前重新核验原科学request、地址、逐块预算、主机/解释器/源码，以及当前可信保活和指定GPU资源。当前worker进程/线程作用域只开放所需七个评测/runtime/simulator边界；训练、旧fleet和直接CLI不开放。

`manage_model_queue.py`提供inspect/prepare/run/recover，缺失或草稿许可在建立运输连接前拒绝。旧暂停保管账本不能转为此入口的运行许可，使用新的本地LIVE_MODEL_V1账本，仍保留原672条任务的预算计划。显式恢复用新owner/epoch，不复用旧PID或旧截止时间。

原任务key和科学地址不变。通用manifest允许显式保留identity_experiment_id，eligible_slots将每块限制在原模型所属主机，避免合并三机控制后错误转派。新结果目录与旧冻结结果分离；旧冻结清单和68f2cd8源码不改。实际科学执行循环的AST在去除权限检查后与冻结版本相同，但CPU等价验证不代替真实首块的轨迹/输入检查。

三机源码部署于独立本地release目录，逐文件核对。GNU/Video既有环境和旧checkout保留，未修改Mac基础服务、代理、认证、保活或tmux。旧冻结源码和其他历史副本仍可由同权限用户手工运行；本措施不宣称操作系统级隔离。正式命令只引用新release与新绑定。

## 实际执行接续

用户随后授权推进原672条真实评测及分阶段多worker执行，不再逐阶段请求确认。原首批48条已完整核验。center的r5控制器只修复队列启动与轮询的交错，以及没有主机可用任务时跳过该slot；三机r4科学执行源码和原运行绑定保持不变。

首次24-worker接续在全部启动后才服务继续许可，导致最早worker超时。24块均在首个guard返回前退出：远端本地执行日志尚未创建、无输出、原进程组已退出、源码哈希匹配，因此明确为零模型执行。一次性显式恢复将完整旧账本、远端启动记录和证明保留到execution/zero-entry-recovery-epoch3；不适用于部分输出或不明消费。已完成48条不重跑，原任务身份与预算不变。修复验证为437 passed/15 skipped，另有三机24个CPU worker故意延迟启动超过60秒后完整完成的证据。

执行状态以新execution目录和center本地账本为准，启动前回执仍作为历史证据保留。
