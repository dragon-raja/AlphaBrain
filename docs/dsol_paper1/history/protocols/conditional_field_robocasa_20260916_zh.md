# 条件视角场与 RoboCasa 扩展｜当前执行计划

更新：2026-09-18。当前GNU广域组已完成8250步；规范组从4000步检查点恢复，正式续训的三步数值验收已通过并继续训练；候选数据保留异常项并继续全400初态构造，尚未正式发布。最新工程状态见6.11，前文各阶段记录保留其历史时点，不代表当前仍未启动训练。用户已确认“左右外部相机联动，腕部安装不变”和“保留原生底盘联动，不修改底盘动作”。旧权重保留为历史对照，主线为新的匹配规范／广域外部增强后训练；全量闭环尚未完成。

## 1. 中心问题与两阶段分工

研究问题：相机扰动后，能否根据当前可获得的观测，预测更有利于固定 VLA 的观察区域，移动后验证并恢复完整任务表现？Accel 暂作代理，不把低 Accel 等同于成功概率。

- LIBERO：机制诊断与方法原型；保留现有规范／多视角两模型和冻结整任务结果。
- RoboCasa：多场景外部验证；主动增加布局、对象配置和任务差异，不只增加同一场景的候选或噪声。
- 当前先研究“操作前调整一次、随后不再主动调整安装偏置”。LIBERO外部相机为世界固定；RoboCasa原生左右相机为底盘安装，随底盘自然运动，不能混称世界固定。腕部安装不变，但其图像随手臂自然变化。保留原生底盘动作，不擅自将其清零以制造固定世界相机。实际移动的时延、可达性和独立噪声确认另行验证。不将仿真相机瞬移写成实体相机运动。
- 当前学习器不必先在小 LIBERO 子集上胜过模板，才允许开展 RoboCasa 场景差异检查；但也不能为了方法获胜而挑选模板失败的场景。

## 2. 第一阶段本轮已完成：相对标签与当前图像场预测基线

数据：8任务×4标准初态×96非规范候选×8评分噪声×2模型。评分噪声与32次完整任务执行噪声不同。原始矩阵不变，无新增科学闭环。

算法：冻结 ResNet18 当前外部图像特征，训练折 PCA 8维；输入当前图像和当前相机三参数坐标，通过岭回归预测96位置的标准化相对指标场。固定 alpha=10，不按评价成绩挑超参数。与固定模板、只输入位姿的基线比较。没有候选目标图像、规范图、任务 ID 或成功标签输入。

重要限制：使用已知任务参考坐标和对齐相机目录，输出为离散场；尚非未知参考位姿、连续 SE(3) 的部署算法。没有任务语言条件，本轮只核验视觉条件能否提供信息，不代表完整设计已测试。

两个划分：

1. 初态留出：初态0/1拟合，2/3评价。
2. 任务留出：只用其余7任务的初态0/1拟合，当前任务初态2/3评价。仍不是新 benchmark 或全面新布局泛化。

每个拟合初态使用64个源视角图，评价使用另32个源视角图。所有96个目标坐标可在训练初态上提供标签；不把源视角留出称为目标坐标未见。

评分噪声前4训练、后4验证，再交换一次。先冻结全部方法选择和模型参数，才读取归档整任务成功标签。源视角和噪声方向先在初态内平均，不把它们当作新增独立任务。

### 2.1 标签结果

同噪声视角差值的方差／假设两个视角独立采样时的方差，先每初态取视角对中位数，再跨32初态取中位数：规范模型 **0.213**，多视角模型 **0.022**。说明本数据中的共同噪声成分很强；不表示预测误差或任务失败率下降同样比例。

相对监督有统计动机，但全量等权两两平方差损失等价于去均值后的平方误差（只差常数倍）。不能把这两个损失同时添加就声称独立创新。下一步设计价值应来自噪声可靠性权重、低值区排序和部署输入约束。

### 2.2 方法结果

下表任务成功率均为选择冻结后查已有整任务终点成绩；不是新的实际获取闭环，也不是单次失败后改赢家。两种噪声划分平均，故模板数字可与旧“8噪声一次拟合”略有不同。

| 规范训练／初态留出 | 87.50% | 91.70% | 61.72% | 60.66% |
| 规范训练／任务留出 | 87.50% | 81.25% | 58.40% | 54.22% |

结论：相对标签值得保留；当前轻量视觉条件模型没有超过强模板，任务留出更弱。不能据此否定更合适表征、任务条件或多场景学习。下一步优先做条件信息与可靠性监督，而非堆网络规模。

## 4. 第二阶段科学设计与决策顺序

1. **复用初始化，重做匹配后训练**：使用同一官方Human300权重初始化新的规范／广域外部增强分支。历史规范与mv_unpaired保留为稀疏全相机增强对照，不替代新主线。这里“规范训练”指本轮续训输入条件，不声称基础模型整个训练史只见过单一视角。
2. **公平训练对照**：原始checkpoint仅作锚点。规范续训与多视角续训必须同初始化、轨迹、动作标签、token与图像数预算、训练步数、优化器、seed、归一化及编码器更新范围。多视角仅改变相机观测，不改变任务状态／动作。不是“旧模型 vs 额外训了一遍的多视角模型”。
   RoboCasa先沿用这些权重对应的OpenPI/JAX链路，不未经等价验收转换进AlphaBrain。LIBERO/PyTorch与RoboCasa/JAX属于不同运行条件；各benchmark内对照固定。Accel移植需核对原10步网格、前三个velocity、动作归一化与有效维度，保留原定义和独立金标准，不把物理轨迹加速度当同一指标。
3. **先审计完整现有初态库，不擅自缩减**：现有seen／heldout各10任务×20初态，共400初态。seen布局ID为11–60，heldout为1–10。完整保留清单；NavigateKitchen应单列导航条件，不无声删除或混入操纵平均值。先做工程子集不是缩小最终总体。旧“4–6任务pilot”只是未冻结提案，不能覆盖现有400初态清单。新增训练先从已有Human300匹配源窗口规划，不擅自改成只训练几个成功任务。
4. **已明确相机干预**：用户选择左右外部联动、腕部安装不变。保持三路输入通道、左右相对位姿与基线。未干预腕部补偿是必须记录的条件，不删相机来放大效果。空间定义先测试三参数rig轨道族（方位、俯仰、半径），与任意SE(3)分开。参考点从规范rig中点和平均光轴构造，不用任务对象真值；它仍依赖已知相机标定，不是无需规范参考的部署方法。深度只服务几何／模块时需明确额外输入权限。
5. **先检查恢复空间**：匹配初态比较原位、扰动、规范参考和少量预定候选。规范条件本身无操作能力时，不能把失败全部归因于视角。
6. **评分广覆盖，闭环有控制**：跨场景生成多噪声Accel标签；不要求所有候选都跑全部任务。完整闭环优先覆盖冻结方法选出的终点和公平对照；代表性预定子集保留密集候选上限。新未测位姿不得插值成功率。
7. **场景划分**：分别声明“选择器未见”和“VLA未见”；场景布局按组留出，不把同布局外观变体分散到训练／测试来冒充新布局。官方target若用于任何适配，不再称该部分对VLA未见。
8. **学习路线**：A冻结VLA、指标场监督 → B冻结VLA、任务反馈训练视角模块 → 必要时C联合更新。C不能只优化Accel，需任务目标与无主动选视角的等预算VLA训练对照。操作前调整与过程中主动控制是另一个独立实验轴。

### 6.1 Accel与完整任务工程链

`AlphaBrain/research/dsol/metrics/pi05_jax.py`保留OpenPI累加时间网格的while-loop，记录归一化动作空间速度，不修改上游库或权重。规范与旧多视角权重各两份显式噪声，原采样器与插桩采样器最终动作最大绝对差均为0，轨迹为`[1,10,50,32]`。使用既有numpy Accel公式，主指标前三个速度；全32维模型输出，不把它当物理12维机器人加速度，也不跨LIBERO的不同动作时域直接比绝对数值。

入口：`scripts/dsol_paper1/runtime/robocasa_policy_probe.py`。完成过四条900步整任务工程轨迹（两种环境初始化诊断×两模型），均未成功；样本太少且新建环境并未配对，不能计算主表成功率，也不能据此断言模型无能力。

发现：即使同时固定Gym、Python、NumPy seed，两个进程的fresh-reset初态仍不相同。该模式只可作功能测试；正式对照必须从同一持久化bundle恢复。已将原审计过的snapshot功能提升到`benchmarks/Robocasa365/snapshot.py`与`snapshot_bundle.py`，原源码保留；仅更换模块位置及旧pickle类名解析，不从归档路径导入运行代码。持续做跨模型初始状态哈希与图像容差验收，不能把模型动作差异与初态差异混为一谈。
